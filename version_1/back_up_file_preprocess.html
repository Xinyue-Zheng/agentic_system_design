preprocessing_stats.json — Complete Field Reference

Step 0 output — all fields computed locally in Python, no API calls. Agents read these as ground truth facts.

coverage_summaryper_usid + area_level — from pixel JSON ▾
per_usid [ USID_XX ] — one entry per base station
tower_lat tower_lonGeographic position of this base station.
Inferred from the first pixel where this USID appears as dominant. Not from any metadata header — real data compatible.
dominant_pixel_count dominant_pixel_fractionHow much of the total area this USID owns — pixels where it has the strongest RSRP signal.
count(dominant.ID == USID) / total_pixels
backup_pixel_count backup_pixel_fractionPixels where this USID appears as 2nd or 3rd strongest (backup1 or backup2 slot). Indicates spatial reach beyond its own dominant area.
count(backup1.ID==USID or backup2.ID==USID) / total_pixels
inferred_roleNetwork role classification based on dominant pixel fraction.
≥30% → dominant-anchor | 10-30% → strong-supporting | 3-10% → localized-supporting | <3% → edge-limited (thresholds: engineering choice — confirm with advisor)
rsrp_sample_countTotal RSRP readings collected from both dominant and backup pixel slots. Broader than dominant-only — captures full spatial reach.
count of all pixels where this USID appears in any slot (dominant, backup1, or backup2)
rsrp_mean_dbm rsrp_p10_dbm rsrp_p50_dbm rsrp_p90_dbmRSRP distribution across all pixels this USID reaches. p10 = weakest 10%, p50 = median, p90 = strongest 10%.
All RSRP samples sorted → index at 0.10 / 0.50 / 0.90 × n
rsrp_pct_above_excellent rsrp_pct_above_good rsrp_pct_above_moderateWhat fraction of pixels receive strong enough signal from this USID. Used for role confidence and Stage 1 quality assessment.
excellent: >-80 dBm | good: >-90 dBm | moderate: >-100 dBm (industry convention — not directly from 3GPP, confirm with advisor)
area_level — aggregated across ALL pixels in the entire network
total_pixelsTotal pixel count in the coverage grid. Grid size derived from unique lat/lon coordinate values — no header metadata required.
len(unique_lats) × len(unique_lons)
sinr_mean_db sinr_pct_excellent sinr_pct_good sinr_pct_moderateSINR distribution across the whole area. Tells Stage 3 whether the network is generally interference-limited (dense urban, low SINR) or noise-limited (sparse deployment, high SINR).
excellent: >20 dB | good: >13 dB | moderate: >0 dB (vendor-defined thresholds — not in 3GPP, confirm with advisor)
throughput_mean_mbps throughput_pct_high throughput_pct_mediumThroughput distribution. In synthetic data computed from Shannon capacity formula; in real data measured directly. Kept for future use in impact quantification.
high: >50 Mbps | medium: >10 Mbps (arbitrary — confirm with advisor)
rsrq_mean_db rsrq_pct_excellent rsrq_pct_goodRSRQ measures signal quality relative to total received power. Poor RSRQ with good RSRP indicates heavy interference. Cross-validates SINR readings.
excellent: >-10 dB | good: >-14 dB (industry convention — confirm with advisor)
sinr_rsrq_consistent sinr_tp_consistentPhysics sanity check flags. Both RSRQ and throughput are monotone functions of SINR — low correlation may indicate measurement artifacts in real operator data.
True if |corr(SINR, RSRQ)| > 0.7 AND |corr(SINR, TP)| > 0.7
capacity_summaryper USID — from attribute CSV, agents read as pre-computed facts ▾
capacity_summary [ USID_XX ] — computed locally in Step 0, never recomputed by agents
capacity_scoreComposite score estimating how much radio capacity this site can provide. Higher = can absorb more traffic after shutdown.
(4G_cells×1.0 + 5G_cells×2.0) × (1 + 0.15×active_band_count) Weights are heuristics — confirm with advisor or replace with PRB utilization.
capacity_formulaHuman-readable audit string showing the exact numbers used in the calculation. Agents and Stage 5 verification can check the score against this string.
e.g. "(6×1.0 + 4×2.0) × (1 + 0.15×3) = 20.9"
active_band_countNumber of distinct frequency bands with at least one configured cell. More bands = more spectrum diversity = higher capacity bonus.
count of {Band_700, Band_1800, Band_2600, Band_3500} columns where value > 0
tower_height_m tower_typePhysical tower height from the attribute CSV and its engineering classification. Taller towers cover larger geographic areas.
<25 m → micro | 25-45 m → macro | >45 m → tall_macro (engineering convention — confirm with advisor)
technology_profileWhether this site is 4G-only, 5G-only, 5G-dominant, or mixed — determined from cell counts. Key input for NSA 5G downgrade risk detection in Stage 2.
5G>0 and 4G=0 → 5G-only | 5G>4G → 5G-dominant | 4G>0 and 5G=0 → 4G-only | else → mixed
operational_roleWhether this site is deployed for wide area coverage (low-band, 4G) or dense traffic capacity (high-band, 5G-heavy).
has Band_3500 + no Band_700 + 5G>4G → capacity-oriented has Band_700 + 5G=0 → coverage-oriented | else → mixed
4G_cells 5G_cellsRaw cell counts from the attribute CSV — the direct inputs to the capacity formula and technology profile classification.
overlap_infosorted list — all USIDs ranked by backup coverage of target's area ▾
overlap_info [ ] — one entry per USID that appears in target's backup slots, sorted by overlap_fraction descending
usidThe USID being evaluated as a potential neighbor of the target. List sorted by overlap_fraction descending — most important neighbors first.
overlap_countHow many of the target's dominant pixels list this USID in backup1 or backup2 — raw count before normalizing.
count(target_dom pixels where backup1.ID==this or backup2.ID==this)
overlap_fractionFraction of the target's dominant pixels where this USID serves as a fallback. The primary ranking metric — Stage 1 uses this to decide which neighbors matter most.
overlap_count / target_dominant_pixels
is_neighborWhether this USID qualifies as an active neighbor — meaning it is a frequent fallback for the target's users. Only neighbors get their own RSRP image generated and appear in Stage 1 analysis.
True if overlap_fraction > 0.05 (5% threshold — mirrors 3GPP SON neighbor list convention in TS 32.541, confirm with advisor)
load_redistributionarea-level + per_backup — impact of target shutdown on each neighbor ▾
area-level — characterization of the target's dominant area as a whole
target_dominant_pixels target_dominant_fractionHow large the target's coverage footprint is — the exact set of pixels directly affected by the shutdown.
count(dominant.ID == target_usid) / total_pixels
coverage_hole_pixels coverage_hole_fractionPixels in the target's dominant area where backup1 is None — no other USID was within the signal gap threshold. These become complete dead zones after shutdown. Expected <5% in a well-planned urban network.
count(target_dom where backup1==None) / target_dominant_pixels
target_dom_sinr_mean target_dom_high_sinr_fraction target_dom_low_sinr_fractionSINR statistics within the target's dominant area only — not the whole network. Used for cross-validation and Stage 3 SINR map correlation.
high_sinr_frac: fraction of target's pixels with SINR >10 dB low_sinr_frac: fraction with SINR <5 dB
dominant_area_severe_fraction dominant_area_mild_fractionFraction of the target's dominant pixels classified as severe or mild impact by the three-signal classifier. Inputs to the area-level regime verdict.
severe = (noise_limited + environment_attenuated) pixels mild = interference_limited pixels classify_pixel_regime(sinr, dom_rsrp, gap=0) per pixel
dominant_area_impact_regimeOverall severity verdict for the target's entire dominant area. Stage 4 hard constraint C3 uses this to adjust the final user impact level.
severe_frac >0.5 → mostly_severe | mild_frac >0.5 → mostly_mild | else → mixed
primary_backup_usidThe single most important backup — the USID that would absorb the largest fraction of the target's traffic after shutdown.
argmax(absorption_fraction_of_target) across all per_backup entries
per_backup [ USID_XX ] — Q1: can it serve? Q2: can it handle load? Q3: how severe is the impact?
absorption_pixel_count absorption_fraction_of_target absorption_fraction_of_totalHow many of the target's dominant pixels fall back to this USID in any backup slot. Note: fractions can sum to >100% because one pixel can be absorbed by two different backups simultaneously.
count / target_dominant_pixels = fraction_of_target count / total_pixels = fraction_of_total
rsrp_in_zone_mean_dbm rsrp_in_zone_p50_dbm rsrp_in_zone_p10_dbmSignal strength this backup provides specifically inside the absorbed pixels — not its overall RSRP, only in the zone it would take over. p10 captures the weakest 10% of pixels this backup would serve.
collected from backup1.rsrp or backup2.rsrp of absorbed pixels → sorted → percentiles
rsrp_pct_above_good_in_zoneFraction of absorbed pixels where this backup provides "good" signal quality (>-90 dBm). Primary input to handover_quality classification.
% of absorbed pixels where backup RSRP > -90 dBm
handover_qualityWhether users can successfully handover to this backup after shutdown — purely a signal quality question, independent of whether the backup is overloaded.
pct_above_good ≥70% → good | ≥40% → partial | else → poor (thresholds: engineering choice — confirm with advisor)
current_dominant_fractionFraction of total area this backup currently dominates before the shutdown — spatial proxy for its existing traffic load before it absorbs anything.
count(dominant.ID == this_backup) / total_pixels
post_outage_load_factor overload_risk load_modeEstimated load on this backup after absorbing the target's traffic. Three possible calculation modes depending on data availability.
spatial_proxy (current placeholder): (curr_frac + absorb_frac) / (capacity_score/10) thresholds: >0.8=high >0.5=medium (arbitrary — replace with PRB) prb_measured (when operator data available): backup_prb_before + (absorption_fraction × target_prb_before) thresholds: >0.85=high >0.70=medium (industry standard, confirm with operator) spatial_proxy_fallback: PRB CSV provided but missing for this USID
sinr_regime_impact_noteSeverity verdict for the pixels this backup absorbs — derived from three-signal classification across all absorbed pixels. This is what Stage 1 cites in its per-backup assessment and what Stage 5 verifies.
(noise_limited + environment_attenuated) >60% → mostly_severe interference_limited >60% → mostly_mild | else → mixed
regime_noise_limited_fraction regime_interference_limited_fraction regime_environment_attenuated_fraction regime_mixed_fractionFull breakdown of the three-signal pixel classification across all absorbed pixels. Gives Stage 3 verifiable ground truth for the sinr_regime field in each impact zone — fixing the verification gap in the old SINR-only approach.
Per absorbed pixel: classify_pixel_regime(sinr, dom_rsrp, gap) → count each regime / absorb_pixel_count Rules inside classify_pixel_regime(): gap>15 + dom_rsrp>-90 + sinr>10 → noise_limited (severe) gap<8 + dom_rsrp>-90 + sinr<5 → interference_limited (mild) gap<8 + dom_rsrp>-90 + sinr≥5 → interference_limited (mild) dom_rsrp ≤ -90 (any gap) → environment_attenuated (severe) gap>15 + dom_rsrp>-90 + sinr<5 → mixed else → mixed
hard_gap_fraction_absorbed easy_gap_fraction_absorbedAmong absorbed pixels, what fraction have a large vs small signal gap between the dominant and this backup. Large gap = backup much weaker than USID_00 was = harder to replace.
hard: (dom_rsrp − backup_rsrp) >15 dB — backup barely qualifies easy: gap <8 dB — nearly co-dominant 15 dB matches backup eligibility boundary; 8 dB aligns with 3GPP A3 event offset
