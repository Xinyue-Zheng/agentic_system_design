## Input data

| File | Location | Description |
|---|---|---|
| `usid_coverage_pixels.json` | `data/input/` | Pixel-level RSRP and SINR measurements |
| `usid_attributes.csv` | `data/input/` | Tower height, band config, 4G/5G cell counts |
| Real map image | provided per run | Geographic map of the target USID area |

## How to trigger

Just describe the outage naturally. Examples:

- USID_00 shutdown 2025-03-18 20:00 to 2025-03-21 20:00
- USID_05 went offline yesterday 8am, back online this afternoon 3pm
- analyse USID_12, outage started March 18 at 8pm and ended March 21 8am

## Your job (Claude Code)

When the user describes an outage:

1. Extract:
   - TARGET_USID  — e.g. USID_00
   - SHUTDOWN_START — format YYYY-MM-DD HH:MM
   - SHUTDOWN_END   — format YYYY-MM-DD HH:MM

2. Run preprocessing first if preprocessing_stats.json does not exist:

```bash
python harness/local_preprocessing.py \
  --coverage-pixels data/input/usid_coverage_pixels.json \
  --attributes      data/input/usid_attributes.csv \
  --target-usid     TARGET_USID \
  --output-dir      data/results/TARGET_USID/
```

3. Then run the pipeline:

```bash
python pipeline.py \
  --target-usid     TARGET_USID \
  --shutdown-start  "SHUTDOWN_START" \
  --shutdown-end    "SHUTDOWN_END" \
  --workspace       data
```

## Re-run from a specific stage after a failure

```bash
python pipeline.py \
  --target-usid     TARGET_USID \
  --shutdown-start  "SHUTDOWN_START" \
  --shutdown-end    "SHUTDOWN_END" \
  --workspace       data \
  --from-stage      N
```

## What the pipeline does automatically

Do NOT run stages manually. The harness handles everything:

  Stage 0  — preprocessing (Python, zero LLM)
  Stage 1+2 — parallel coverage and attribute analysis
  Stage 3  — geographic correlation (requires real map image)
  Stage 4  — final assessment (context reset)
  Stage 5A — deterministic numeric checks (Python)
  Stage 5B — adversarial LLM verification
  Stage 6  — ACE Reflector (warm tier update, PASS only)

Output: data/results/TARGET_USID/stage4_final_TARGET_USID.json

## If the pipeline stops

Read the error message — it tells you exactly which stage failed.
Ask the user whether to fix and rerun with --from-stage N.
Do not attempt to fix prompt files or schema files yourself.
